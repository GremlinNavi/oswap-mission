# OSWAP Mission Governance

Status: Draft v0.1

## Purpose

This document governs changes to the mission-level documentation in this repository. It does not replace component-specific governance or technical standards.

## Mission changes

Changes that materially alter OSWAP's stated purpose, public-interest commitments, scope boundaries, or hosting-independence principles should:

1. be proposed through a reviewable change with a clear rationale;
2. identify which mission documents are affected;
3. distinguish editorial clarification from a substantive change in project purpose;
4. preserve historical versions where practical; and
5. avoid retroactively describing experimental or planned capabilities as if they had already existed.

## Documentation status

Mission documents may use maturity labels such as Draft, Proposed, Accepted, or Deprecated. A maturity label describes documentation stability; it is not a legal certification or standards-body designation.

## Hosting and mirrors

GitHub and GitLab copies of this repository are intended to carry equivalent published mission documentation. Neither hosting provider is the authority that defines OSWAP's mission.

Temporary divergence caused by authentication, transport, review, or publication failures should be documented and reconciled rather than hidden. Force-push history rewriting should not be the normal synchronization mechanism for published mission records.

## Forks

Forks are welcome under the repository license. A fork may change its own mission, but materially changed forks should not imply that their altered mission text is the current mission of the upstream OSWAP project.

## Technical authority

Mission documentation establishes project direction. Technical behavior remains governed by the applicable schemas, standards, parsers, tests, security boundaries, and implementation documentation in component repositories.

## Legal and institutional status

This governance file does not establish OSWAP as a corporation, charity, government body, accredited standards organization, or other legal entity. Any such status must be documented separately if and when it exists.
